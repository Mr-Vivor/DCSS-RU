# WebTiles на VPS

Проверенные Linux-сборки устанавливаются в `/srv/dcss-ru/releases/<git-sha>`.
`current` указывает на активный релиз. Аккаунты, настройки, сохранения и морги
лежат в `shared/`, отдельно от сборки и Git. `repository.git` — зеркало публичного
репозитория; доступ к GitHub для чтения исходников не требует секрета на VPS.

Первичная установка на Ubuntu 24.04: установить `python3-venv` и библиотеки
движка, загрузить эти файлы и артефакт `dcss-ru-web-ubuntu24` из зелёной сборки,
затем от root выполнить:

```sh
sh bootstrap.sh /tmp/dcss-ru-web.tar.gz <полный-git-sha>
```

Сервис `dcss-ru` работает от отдельного пользователя и слушает
`127.0.0.1:8088`. Для тестирования до настройки DNS/HTTPS:

```sh
ssh -N -L 8188:127.0.0.1:8088 root@<сервер>
```

После этого открыть `http://127.0.0.1:8188/`. Аккаунты создаются через веб-лобби;
обычная игра и обучение используют отдельные игровые процессы.

GitHub Actions отправляет готовый архив только после проверки словарей, C++
и создания персонажа в Chromium. Нужны secrets `DCSS_DEPLOY_HOST`,
`DCSS_DEPLOY_USER`, `DCSS_DEPLOY_KEY`, `DCSS_DEPLOY_KNOWN_HOSTS`, а также
repository variable `DCSS_DEPLOY_ENABLED=true`.

Отдельный SSH-ключ пользователя `dcssdeploy` ограничен единственной командой:

```text
restrict,command="/srv/dcss-ru/bin/receive-release.py" ssh-ed25519 <публичный-ключ>
```

Команда принимает `deploy <sha>` и архив через stdin. Оболочка, интерактивный
доступ и перенаправление портов этому ключу недоступны. Основной SSH-ключ
администратора не передаётся в GitHub. Привилегированная активация проверяет
пути, размер архива, типы файлов и ELF-заголовок движка.

Если есть запущенные партии, релиз остаётся ожидающим. Таймер
`dcss-ru-apply` проверяет возможность обновления раз в минуту. Перед переключением
создаётся резервная копия SQLite через backup API, сохранений и настроек.
При неудачной HTTP-проверке восстанавливается предыдущий релиз.

Полезные команды:

```sh
systemctl status dcss-ru
journalctl -u dcss-ru -n 50
cat /srv/dcss-ru/current/REVISION
cat /srv/dcss-ru/pending.json
systemctl start dcss-ru-apply
```

Публичный доступ настраивается отдельным HTTPS-виртуальным хостом Nginx с
проксированием HTTP и WebSocket на порт 8088. Основные сайты сервера используют
свои конфигурации. Папки `backups/` и `releases/` автоматически не удаляются;
нужно следить за свободным местом и сохранять необходимые копии вне VPS.
