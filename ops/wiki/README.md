# Русская вики DCSS

Адрес: **https://wiki.dungeoncrawl.ru/**. MediaWiki **1.43.11 LTS**, PHP 8.3,
Vector с темой проекта. Сертификат Let's Encrypt отдельный, продлевается Certbot.
Публичный TLS/SNI-маршрутизатор VPS направляет домен на существующий внутренний
HTTPS-порт Nginx `127.0.0.1:9443`; остальные сайты и игровой сервис не меняются.

## Данные и доступ

- Код MediaWiki: `/srv/dcss-wiki/releases/mediawiki-1.43.11`, ссылка `current`.
- Основная база: `/srv/dcss-wiki/shared/data/dcsswiki.sqlite`.
- Отдельные SQLite-файлы локализации, очереди и кэша создаются самой MediaWiki.
- Загрузки: `shared/images`; тема и логотип: `shared/resources`.
- Настройки и секреты: `/etc/dcss-wiki/LocalSettings.php`; проектные настройки
  подключаются из `/etc/dcss-wiki/ProjectSettings.php`.
- PHP работает в отдельном пуле от пользователя `dcsswiki`.
- Чтение публичное. Анонимные правки и самостоятельная регистрация отключены
  по выбору владельца. Администратор `Vivor` создаёт редакторов через служебную
  страницу создания учётной записи после входа.
- Первоначальный пароль находится в `/etc/dcss-wiki/admin-password` с режимом
  `0600`. Секреты не включаются в Git, wiki-пакет или артефакты Actions.

При первом развёртывании скопировать эту папку в `/tmp/dcss-wiki-ops`, загрузить
официальный архив `mediawiki-1.43.11.tar.gz` в `incoming` и выполнить от root:

```sh
sh /tmp/dcss-wiki-ops/bootstrap.sh
```

Скрипт проверяет отсоединённую GPG-подпись по ключам, опубликованным MediaWiki,
устанавливает отдельный PHP-пул и конфигурацию домена. Существующая база и
учётная запись при повторном запуске сохраняются. HTTP обслуживает проверку
ACME до готовности DNS; затем включается HTTPS. `dcss-wiki-https.timer`
повторяет проверку DNS раз в 15 минут и отключается после выпуска сертификата.

## Подготовка и импорт содержимого

Из корня репозитория, с Python и PyYAML:

```sh
python tools/wiki/build.py --output /tmp/dcss-wiki-content
python tools/wiki/check.py /tmp/dcss-wiki-content
```

Генератор использует общий словарь, проверенные описания, текущие YAML-данные
видов/предысторий/существ, определения заклинаний и оригинальные PNG игры.
Собственные руководства и тема хранятся в `wiki/site/`. Снимок исходных
редакций CrawlWiki находится в `wiki/site/community-revisions.json`; это
атрибуция и ссылки, а не автоматический перенос старых чисел в новую версию.

Полный исходный текст выбранных статей можно получить отдельно:

```sh
python tools/wiki/fetch_community.py titles.json community-sources.json
python tools/wiki/build.py --output /tmp/dcss-wiki-content --community community-sources.json
```

Первый импорт на VPS:

```sh
runuser -u dcsswiki -- php /srv/dcss-wiki/bin/update-content.php --initial /path/pages.json
cd /srv/dcss-wiki/current
runuser -u dcsswiki -- php maintenance/run.php importImages /path/sprites --user=Vivor
```

Сначала создаются описания файлов, потом загружаются картинки, чтобы источник
и авторство не терялись под стандартной подписью загрузчика. Файлы логотипа,
favicon.png и theme.css копируются в `shared/resources`.

Публикуемый блок окружён метками `DCSS-AUTO-BEGIN/END`. Обновление сохраняет
текст редактора вне блока. Если содержимое самого блока изменили вручную,
новая версия пропускает его и записывает конфликт в `shared/import-conflicts.json`.
Обычные перенаправления и короткие системные сообщения проверяются по полному
отпечатку. Никакие страницы, правки и картинки при синхронизации не удаляются.

## Автоматическое обновление через GitHub

Actions строит и проверяет wiki-пакет, доступный как `dcss-ru-mediawiki-content`.
На VPS `dcss-wiki-sync.timer` каждые две минуты проверяет **активный**, уже
протестированный игровой релиз из `/srv/dcss-ru/current/REVISION`.

`sync.py` читает этот коммит из существующего публичного Git-зеркала, собирает
контент и обновляет MediaWiki. Он работает от `dcsswiki`, не использует пароль
администратора или новый SSH-ключ и не переключает игровые релизы. Если игровое
обновление ждёт завершения партий, вики тоже остаётся на предыдущей версии.
Временные исходники удаляются по окончании обработки; копии всех релизов вики
не накапливаются. Сведения о последней обработке — `shared/sync-revision`
и `shared/build-report.json`. Файл `shared/search-extracts.json` даёт поиску
читаемые русские выдержки без HTML-разметки карточек.

Фоновая очередь ссылок и категорий обрабатывается `dcss-wiki-jobs.timer` раз
в минуту. После большого первого импорта её можно дополнительно обработать
командой `maintenance/run.php runJobs --maxtime=300 --maxjobs=12000` от `dcsswiki`.

## Резервные копии

`dcss-wiki-backup.timer` ежедневно создаёт согласованный снимок основной SQLite
базы через backup API и архивирует его вместе с загрузками, настройками и
состоянием импорта. Архивы в `backups/` доступны только root. Хранятся семь
последних управляемых архивов; игровая папка резервных копий не затрагивается.
Кэш, очередь задач и локализация не являются основным содержимым и не входят
в снимок базы. Перед ручным восстановлением остановить PHP-пул вики и фоновые
обновления, сохранить текущие данные, затем восстановить базу и файлы с их
владельцами и выполнить штатное обслуживание MediaWiki. Не подменять данные
работающего SQLite-процесса простым копированием файла.

```sh
systemctl start dcss-wiki-backup.service
systemctl list-timers 'dcss-wiki-*'
journalctl -u dcss-wiki-sync.service -n 30
```
